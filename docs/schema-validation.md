# Record schema validation

Runtime dependencies remain stdlib-only. Development tests use `jsonschema` from the `test` extra to check Draft 2020-12 documents and fixtures without fetching remote schemas.

| Record | Structural schema | Runtime enforcement |
| --- | --- | --- |
| protocol / owner / state | Existing schemas; valid templates and invalid version/missing-field cases | Public contract parser and authority validation |
| Public result | result.schema.json delegates host commands to strict host-result.schema.json | Host factory and final serializer enforce command-specific fields/types/required successful data and reject private evidence/ownership/publication/shared-secret claims; remaining command families are incomplete |
| Prepared session candidate | session-candidate.schema.json | Strict fields/types/version/protocol, IDs, identity digests, nullable acquisition OID |
| Active or revoked private session | session.schema.json | Candidate rules plus nonnull acquisition OID; caller binding/history and revocation checks |
| Private Git journal | git-journal.schema.json | Strict fields/types/version, operation/phase/result, timestamp, expected-absent init and exact acquisition candidate intent |
| Decision envelope / lifecycle | decision.schema.json / decision-state.schema.json | Immutable reviewed scope/mode/project/config/upload intent, unique options, exact observations and strict terminal lifecycle |
| Authority configuration | config.schema.json | Explicit validated destination, distinct publication/mainline refs and supported Plan directory |
| Caller authority selection | authority-selection.schema.json | Strict version/fields, caller/checkout/authority digests and nullable transition ID |
| Authority transition journal | authority-transition.schema.json | Prepared/resolved outcome consistency, nested selection shapes; runtime additionally checks distinct authorities, caller/transition linkage and exact durable commit point |
| Authority transition decision evidence | authority-decision.schema.json | Exact observations and target descriptor; runtime additionally validates computed identities, public reviewed effects, source binding, caller lifecycle and preservation linkage |
| Markdown Plan metadata | plan.schema.json | Required descriptions, status and unique stable Step IDs; Git checks enforce Plan history/reference invariants |
| Nonsecret secrets manifest | secrets-manifest.schema.json | Classifications, required flags, file mapping safety, provider-key restrictions and nonoverlapping mapped paths |
| Secret baseline | secret-baseline.schema.json | Strict version/fields, repository/config/sync IDs and approved scope; values remain private |
| Private secret binding | secret-binding.schema.json | Strict version/fields, manifest, explicit mode/destination identity; local-env cannot grant shared writes; validation before saving and reading |
| Host observation | host-preservation.schema.json | Private bounded metadata/digest tree; strict handle/filename/scope, regular/directory/symlink type checks; public results contain no file digests |
| Host file backup | host-backup.schema.json | Strict private fields and bounded metadata/bytes; runtime verifies canonical path, owner/group, digest/base64/size, handle linkage and private byte-restoration rehearsal |
| Host file recovery journal | host-recovery.schema.json | Prepared/resolved outcome pairing and IDs; runtime verifies same-path original/current handles, caller filesystem permissions, editor preconditions and no-replay resolution |
| Private secret decision | secret-decision.schema.json | Explicit binding/reconcile variants; strict fields/version, decision/filename linkage, nested candidate/previous binding and public category/authority agreement |
| Secret plan | secret-plan.schema.json | Strict lifecycle, identity/filename, source evidence and scoped target/conflicts; original intent recomputed from B/L/R before apply, source plan checked before recovery effects |
| Secret journal | secret-journal.schema.json | Strict outer fields/version/phases/per-key status; nested local/shared evidence, binding/manifest/identities, dotenv raw/value agreement, exact observed per-key intent, filename identity, distinct operation IDs and no unresolved sends in terminal phase |
| Local dotenv patch | local-secret-patch.schema.json | Strict private input shape and values; unique deletion approvals must name selected null targets; invalid inputs do not change material |
| Integrity review observations | integrity-decision.schema.json | Exact decision/public observation linkage, snapshot validity, previous trust classification/OID and private dependency digests; dependency changes invalidate adoption before reads/effects |
| Trusted authority baseline | integrity.schema.json | Strict version/fields/OID, exact authority identity and descendant history; invalid records block mutation before sending |
| Preservation handle | preservation.schema.json | Strict retained-checkout evidence, canonical path/handle linkage, index hash/stage bytes, NUL status parsing and source-derived counts; corrupted linked evidence blocks integrity adoption before remote observation |

`tests/fixtures/records` contains explicit valid/invalid private record fixtures. Tests also validate real acquisition journal/session records and demonstrate that corrupt journal records prevent mutation before a network send. Journal filename and record identity must match, including during pending-barrier scans.

Cross-field equality and Git history cannot be represented by these structural JSON Schemas alone. Runtime verifies candidate session/operation/repository/ref equality, candidate acquisition OID matching the prepared commit, caller context/checkout binding, and acquisition history. Unknown publication outcomes cannot have a resolved phase. A malformed record fails closed rather than being skipped by a pending scan.

Secret binding proposals now persist their complete public approval details in the immutable envelope. Apply checks the private candidate against that reviewed scope and destination; changing private scope cannot reuse old consent. Tests cover envelope corruption, duplicate options, incompatible lifecycle versions and private candidate scope changes without effects.

OID schemas allow SHA-1 or SHA-256 shapes; current Git backend explicitly supports SHA-1 only. Shape acceptance does not establish backend capability.

This is partial schema coverage. Command-specific public result extensions and broader record fixture matrices still require complete schemas and coverage. The integrity schema above covers the private trusted baseline. This document does not claim complete Design v1.2 record validation.

The shared journal evidence schema rejects unknown fields and malformed nested records. Runtime checks additionally enforce binding identity, approved key scope, PEM framing, dotenv/source consistency, upload grants and exact uploads/downloads derived from observations. Corruption tests prove rejection before Git observation/provider reads or baseline advancement. Schema tests resolve references from an explicit local file URI and in-memory schema store.

Host public contracts cover bare error, inspect/verify, backup/verify-backup and restore/resolve. Four tests cover realistic records, invalid fields/types/claims, missing success evidence, category contradictions and safe serialization after command identity mutation. Cross-list consistency is additionally enforced by stdlib runtime checks. Other public command families still need equivalent extension contracts; this does not establish complete result-schema coverage.

Authority public contracts now cover propose/apply/resolve and bare errors via authority-result.schema.json. Stdlib checks prohibit publication/ownership/provider grant claims, require a scoped switch/abort authority decision with a preserved-source handle, validate complete selection outcome groups, and reject same source/target identity. Factory/final serializer enforce family identity and safe fallback. Three real-fixture tests validate schema/runtime agreement, malformed decisions/partial evidence and suppressed command-identity mutation. Git/secret/context/inspection result families still require equivalent complete contracts.

Inspection/status/context results now use info-result.schema.json and stdlib factory/final serializer guards. Inspection contains only revision, advisory owner presence, runtime status and protocol version; no raw records or capability/publication claims. Completed context creation contains only an absolute canonical private file address, never the token. Four tests verify real inspection output, unsafe nested fields/claims, nonstring command mutation and relative-root context creation without token disclosure. Git mutation/resume/decision and secrets result families remain incomplete.

Git mutation results now use git-result.schema.json and stdlib factory/final serializer validation. Published outcomes require operation/revision identifiers; recovery cannot publish, non-handoff commands cannot claim shared-secret convergence, takeover proposals require preservation and observed owner/head, and test_status remains unknown. Handoff nested secret summaries reject values/private keys. Public-result failure after effects is distinct from input errors: CLI reports publication_unknown/ownership_pending and preserves a well-formed operation address when available, rather than claiming no mutation occurred. Three real-fixture tests cover lifecycle/schema agreement, false test/shared/recovery claims, nested private data rejection and post-effect serializer failure followed by exact resolution. Resume/decision and direct secrets results remain incomplete.

Resume results now use resume-result.schema.json and factory/final serializer guards. Ready requires owned/revision/managed-checkout/preservation evidence, no unresolved publication marker and complete required local material; local availability never claims shared convergence. Takeover offers retain scoped decision evidence. Three public-result tests plus a real materialization/takeover regression verify readiness rejection and no false owned claim after fencing. Decision and direct secrets result contracts remain incomplete.

Control integrity results now use control-result.schema.json: preserved-source adopt/abort offers only, no restore/publication/capability/provider grants, typed observation for adoption, safe error envelopes. Integrity proposal no longer returns before the shared CLI serializer, and final family identity/field validation catches post-return contamination. Three fixture tests cover real proposal/adopt agreement, wrong scope/unsupported restore and the prior serializer bypass. Direct secrets result contracts remain incomplete.

Direct secrets results now use secrets-result.schema.json and stdlib command-specific validation. Only scoped key names, opaque operation/plan/backup IDs, public decisions and typed availability/conflict summaries are allowed; secret values, raw dotenv/PEM, hashes and publication/capability claims are rejected. Inspect cannot claim shared convergence; verified shared read requires a verified convergence marker. CLI preserves a known secret operation address and returns unknown after unsafe post-effect serialization. PublicResultFailure bypasses generic secret IO failure handlers so a verified terminal journal is not rewritten as invalid unknown. Four fixture tests cover local flow/schema agreement, missing material/false claims, post-effect mutation and factory failure with preserved terminal evidence. Complete per-family semantic/cross-field audit remains outstanding.

The global result registry enumerates every supported public command and routes each to a closed family contract. Unknown labels are rejected; generic error commands cannot claim successful execution or carry extra fields. `tests/test_result_registry.py` checks schema/runtime registry parity, extra-field rejection for every registered command, and safe invalid-CLI errors. The full 213-test suite passes; this structural coverage does not replace backend acceptance evidence.
