# Support and capability matrix

This matrix describes the implemented or advertised boundary, its enforcement point, and existing negative evidence. “Unsupported” is not a claim that every unsupported combination has a dedicated test. Untested combinations remain candidates, not supported features. The project verifies Python 3.12 on WSL Ubuntu; metadata `>=3.12` is only the installation floor and later minor versions remain unverified; Windows is the editing host, not a claimed native runtime.

| Area | Advertised / enforced boundary | Enforcement point | Existing negative evidence and limit |
| --- | --- | --- | --- |
| Runtime platform | Python 3.12 is verified; `>=3.12` metadata permits installation but does not certify later minors. Supported smoke scope is Ubuntu on WSL. README explicitly marks native Windows and macOS unsupported. | `pyproject.toml`; platform-specific sandbox denies non-Linux before target execution in `scripts/landlock_tool_child.py::_landlock_syscalls`. | `tests/test_landlock_tool_child.py::test_non_linux_platform_fails_closed_before_exec` proves the child sandbox gate only; there is no whole-runtime native-Windows/macOS test. Do not infer Windows-native support from the Windows editing workflow. |
| Git object format | Runtime accepts full lowercase 40-hex commit IDs (SHA-1). README declares SHA-256 repositories unsupported. | `src/agent_handoff/git_backend.py::GitBackend.remote_head` rejects any remote OID not matching 40 lowercase hex; terminal receipts also require a full 40-hex OID. | `tests/test_git_timeout.py::test_rejects_ambiguous_truncated_or_wrong_identity_receipts` rejects malformed/wrong receipt identity. `tests/test_git_unsupported_boundaries.py` rejects a real SHA-256 authority before fetch and preserves its ref, source/index and local trust state. |
| Submodules and Git LFS | Unsupported in publication snapshots. | `GitBackend.records` rejects mode `160000` entries and `.gitattributes` entries containing `filter=lfs` with `unsupported`. | Actual Gitlink, root LFS and nested LFS committed-tree fixtures reject readonly inspection without publication or source/private-state mutation. |
| Git authority destination | Caller must provide explicit local path, HTTPS URL, or SSH URL/SCP form; embedded credentials, helper protocols, option-like values, whitespace/control characters and ambiguous aliases are rejected. | `git_backend.py::validate_destination`; Git subprocess uses fixed argv, sanitized Git environment, disabled hooks and fsmonitor. | `tests/test_foundation.py::test_credentials_and_helpers_rejected`, `test_explicit_scp_authority_is_preserved_without_alias_inference`, and `test_mutation_requires_explicit_authority_and_is_json_only`. `test_real_git_pinned_inspection_preserves_worktree` covers pinned readonly inspection; no general repository-hook execution feature is advertised. |
| Git command execution | Runtime invokes Git with its own explicit authority/ref and fixed environment; it does not accept a repository-defined executor. Hook and fsmonitor behavior is disabled for runtime subprocesses. | `GitBackend.run` passes fixed `core.hooksPath=/dev/null`, `core.fsmonitor=false`, explicit `-C`, structured arguments, and `git_environment()`. | `tests/test_foundation.py::test_real_git_pinned_inspection_preserves_worktree` verifies inspection does not mutate its checkout; timeout tests verify bounded process cleanup. `tests/test_git_unsupported_boundaries.py` proves configured pre-push and source fsmonitor helpers execute in plain-Git controls, then remain unexecuted by backend publication and source preservation respectively. |
| Local secret mode | `local-env` is an explicit supported mode; dotenv parsing and journaled local patching are limited to declared keys and exact local observations. | `secrets/local_env.py`, `dotenv.py`, `manifest.py`, and `SecretService.apply_local` validate scope and use durable local-patch evidence. | `tests/test_secret_cli.py::test_local_env_configure_decision_private_patch_verify_flow`, `tests/test_secret_service.py::test_ordinary_local_patch_process_crash_after_rename_resolves_without_replay`, and `test_local_patch_journal_rejects_out_of_scope_target_env_change`. |
| File-backed secret mappings | Supported only for approved relative text-PEM mappings. Traversal, symlink/hardlink/non-private files, tracked mappings, binary PFX/P12, unsafe suffix publication, and mapping overlap are rejected. | `secrets/manifest.py::parse`, `secrets/file_material.py::FileMaterial`, snapshot validation. | `tests/test_secret_service.py::test_file_backed_tracked_source_and_binary_are_rejected`, `test_file_backed_nonsecret_suffix_cannot_enter_git_snapshot`, `test_file_backed_editor_change_invalidates_observation`; `tests/test_file_material.py::test_invalid_pem_binary_and_escaping_mapping_fail_closed` and `test_symlink_directory_and_hardlink_are_never_written` cover mapping/material rejection. |
| Doppler adapter | Explicit project/config and requested keys; CLI 3.58.0+ distinguishes restricted values. User-approved basic writes require upload authorization, expected-value preflight and verified readback. Unknown outcomes resolve by current-state observation without replay. No atomic cross-service fence or same-key CAS is advertised. | `secrets/doppler.py::Doppler.read`, `write_key`; `SecretService` checks current ownership and scope. | `tests/test_doppler_basic_write.py` covers input transport, conflict, rejection and unknown outcomes; `tests/test_secret_service.py` covers baseline preservation and observation-based recovery. Actual-provider evidence is tracked separately from fake tests. |
| Claude MCP profile | The reviewed profile allows only exact `claude-haiku-5-5`, one `handoff` server and two tools (`read_file`, `agentctl`); unexpected native tools, servers, model, or command/result shapes fail closed. | `scripts/provider_mcp_profile.py::claude_mcp_command` and `claude_mcp_trace`. | `tests/test_provider_mcp_profile.py::test_profile_rejects_extra_server_and_cannot_overwrite_destination`, `test_trace_rejects_unapproved_registry_model_and_uncorrelated_ids`, and `test_trace_rejects_wrong_command_result_nontext_and_reordered_result`. The third actual MCP auth turn passed its readonly A35 scope; earlier failures remain retained. This does not prove a feature-edit workflow. |
| Claude feature MCP profile | Exact Haiku 5.5, one server and three tools: canonical `read_file`, action-only `agentctl`, and owned `project_file` read/conditional-write/resolve for approved `app.py`. No native shell or file tools. | `provider_feature_mcp_profile.py`, `provider_feature_broker.py`, `provider_project_files.py`, and `provider_mcp_feature_smoke.py`. | Approved actual provider turn in [feature evidence](feature-workflow-evidence.json) passed; original trace/journal/Git state passed current verifier offline. Fourteen controller tests include real engine/Git two-edit integration and failure preservation. Scope is local Git and synthetic Doppler; no shared secret writes are proved. |
| Broker tools and engine calls | Broker exposes only approved `read_file` and constrained `agentctl` phases. Requests cannot supply executable, policy, grants, environment or arbitrary shell commands. | `scripts/provider_tool_broker.py::Broker` validates MCP schemas, allowlisted file paths and public runtime results before execution. | `tests/test_provider_tool_broker.py::test_duplicate_and_oversized_frames_exit_without_tool_execution`, `test_read_rejects_additional_arguments_and_noncanonical_alias`, `test_agentctl_rejects_unsafe_commands_arguments_and_raw_stderr`, and `test_agentctl_rejects_valid_result_for_a_different_command`. Actual installed-engine evidence is separately scoped in `docs/provider-broker-engine-evidence.json`. |
| Landlock child isolation | Linux-only filesystem read grants are exact files/directories under ABI 1. It is not a network sandbox, arbitrary-executable confinement, truncate protection, or complete filesystem-integrity boundary. | `scripts/landlock_tool_child.py::_load_policy`, `_landlock_syscalls`, and fixed child environment; unsupported platform/ABI fails before exec. | `tests/test_landlock_tool_child.py::test_context_file_shell_symlink_and_listed_directory_do_not_grant_file_reads`, `test_policy_rejects_duplicate_unknown_alias_and_protected_ancestor`, and `test_non_linux_platform_fails_closed_before_exec`. Broker exposure is limited to fixed readers and typed engine calls; do not advertise arbitrary shell/Python as confined by Landlock. |
| Fresh provider evidence | Codex and Claude have distinct historical successful bootstrap records; Claude's MCP isolation/auth diagnostic is separately proven in a readonly local-Git/synthetic-Doppler scope. | Historical native-tool bootstrap constructors now reject with `legacy_provider_profile_not_isolated`; Claude exclusive MCP uses profile, broker and `provider_mcp_auth_smoke.py`. | `docs/provider-bootstrap-evidence.md` and `docs/claude-bootstrap-evidence.md` record scoped A59 success; `docs/claude-mcp-auth-evidence.json` records the third fresh readonly A35 pass; the second turn failed ordering and remains retained. Codex success is not evidence of Claude MCP confinement, or vice versa. |

The rows above do not claim a complete Cartesian test of platform × Git host × provider × CLI version. The current support contract is bounded to the declared environments and capabilities; missing negative fixtures are identified explicitly rather than treated as successful coverage.

Legacy native-tool provider launch is disabled at the shared command constructors before model subprocess execution. `tests/test_provider_bootstrap_smoke.py::test_legacy_provider_constructors_fail_before_spawn` covers both providers; `test_legacy_interaction_turn_rejects_before_files_or_provider_spawn` covers the interaction call boundary. The separate three-tool Claude feature profile has the scoped evidence described above.
