# Snapshot / Recovery Acceptance Audit (A11–A20)

Scope: Design v1.2 §20.2–§20.3, relevant §9–§10, §12–§14, §25 and the corresponding `docs/spec.md` publication, snapshot, and unknown-outcome rules. Tests were read with their `RepositoryFixture` setup; live records were checked for the actual operation and execution boundary they report.

`proven_local` means the requirement-level behavior is asserted in local runtime/backend tests. `proven_hosting` means relevant behavior also appears in an executed hosting record. `incomplete` means an explicit branch or required assertion is missing. A local loopback Git wire fixture is not labeled live hosting; a process-fault hook after server acceptance is not described as packet loss.

## Material gaps

- A14 is now covered for omitted, false and true intent locally; hosting evidence remains limited to explicit false.
- A18 has strong local fault-injection evidence but no live hosting runtime timeout with a competing publication. Design §20 does not require every acceptance case to run on hosting; this is a scope limitation, not a failed hosting requirement.
- A16/A20 crash hooks execute after the server accepts a real Git write but before the runtime processes the result. They do not establish behavior under actual packet loss, delayed hosting policy, or arbitrary network failure.

Primary review strengthened A11 exact payload/state/owner assertions and added A14 true intent. The full suite passed 245 tests; the final 13-test snapshot module also passed after strengthening A11. A17 now additionally has 22 focused backend/publication tests and Primary review of the strengthened fresh-operation case. No material A11–A20 local-scenario gap remains in this audit; the full A01–A63 and §25 audit remains open.
