# 使用者指南：固定輸入與回報

**本指南是使用者用語的統一來源。** README、對話示範與 Agent 指令沿用同一份範本，不另寫意圖不同的版本。首次導入的範圍是：**安裝、導入、保存初始進度、驗證，然後停下回報。** 開始功能開發由你下一次交代。

這些文字是給 Coding Agent 的工作說明，不是引擎辨識的固定口令。請使用能讀寫專案檔案、執行終端機的 Coding Agent；一般網頁聊天若沒有這些權限，無法代你安裝。目前工具執行環境是 Ubuntu／WSL，環境檢查由 Agent 處理。

## 1. 從 GitHub 開始：只用這份輸入範本

在 Agent 對話中貼上下面內容，只替換三個大括號欄位。工具本體與你的產品專案分開放置，取得工具與安裝由 Agent 負責。

<!-- onboarding-input:start -->
```text
請導入 Agent Handoff。
工具：https://github.com/sifeng86/agent_handoff_cli
專案名稱：{專案名稱}
專案位置：{專案路徑}
專案狀態：{全新專案或既有專案}
請由你閱讀工具說明，完成安裝、專案指令整合、初始化、初始進度保存與交接驗證。工具與產品專案分開放置，保留原有工作與 Agent 指令。
這次只完成導入與驗證，停下來按固定格式回報，不開始功能開發。需要我登入或做必要決定時再問我，其餘由你操作。
```
<!-- onboarding-input:end -->

## 2. 兩種案例怎麼填

| 案例 | 專案狀態填什麼 | Agent 要處理的事情 |
| --- | --- | --- |
| 全新專案，剛要開始 | `全新專案` | 建立或使用目標資料夾，準備 Git 初始版本，導入指令與交接設定，保存初始進度並驗證 |
| 專案已進行到一半 | `既有專案` | 先保留現有修改、整合既有 Agent 指令，整理已完成／進行中／待辦，再保存可接手的進度並驗證 |

兩種案例都使用上面同一段輸入，只改欄位。若缺少專案 repository、登入或必要決定，由 Agent 檢查後補問。既有專案的未提交修改不會因為複製 template 就自動保存，Agent 必須確認並安全整合；無法確認的進度不得自行算成完成。

假設 `hahaha` 已經進行一段時間，位置是 `~/workspace/hahaha`，完整內容如下，與第 1 節只有三個欄位值不同：

```text
請導入 Agent Handoff。

專案名稱：hahaha
專案位置：~/workspace/hahaha
專案狀態：既有專案
請由你閱讀工具說明，完成安裝、專案指令整合、初始化、初始進度保存與交接驗證。工具與產品專案分開放置，保留原有工作與 Agent 指令。
這次只完成導入與驗證，停下來按固定格式回報，不開始功能開發。需要我登入或做必要決定時再問我，其餘由你操作。
```
<!-- onboarding-hahaha:end -->

如果 hahaha 是全新專案，只把 `專案狀態：既有專案` 改成 `專案狀態：全新專案`。

## 4. Agent 必須用什麼格式回報

回報的欄位名稱與順序固定。專案資料與結果填入實際值，不能把範例當成已執行的結果。

<!-- onboarding-report:start -->
```text
導入結果：{已完成／待確認／未完成}
專案名稱：{專案名稱}
專案位置：{使用者提供的專案路徑}
專案狀態：{全新專案／既有專案}
原有工作：{已保留／未確認／不適用（全新專案）}
交接設定：{已建立／未完成}
初始進度：{已保存／未保存}
交接驗證：{通過／未驗證／未通過}
目前工作：{已停止，等待下一個指示／已停止，等待處理問題}
```
<!-- onboarding-report:end -->

「待確認」或「未完成」時，後面再加 `原因：…` 和 `需要你處理：…`，說明具體問題與下一步。缺少登入、授權或資料時用「待確認」；錯誤、未收斂或結果不確定時用「未完成」。

**只有這些條件都成立，才能回報「已完成」：**

- 原有工作已保留；全新專案若原本無工作則為不適用。
- 交接設定已建立，初始進度確實保存並讀回確認。
- 交接後的狀態已驗證可供接手，寫入權限已釋放。
- 本次工作已停止，尚未開始功能開發。

未驗證就填「未驗證」，不能用「應該可以」「基本完成」或只說「搞定了」代替結果。

### hahaha 成功時應看到的回報

以下只是格式示例；Agent 必須先實際完成與驗證，才能給出這些結果：

```text
導入結果：已完成
專案名稱：hahaha
專案位置：~/workspace/hahaha
專案狀態：既有專案
原有工作：已保留
交接設定：已建立
初始進度：已保存
交接驗證：通過
目前工作：已停止，等待下一個指示
```

## 5. 導入完成後

收到「已完成」且各項驗證通過，再告訴 Agent：「請繼續 hahaha 目前未完成的任務，先說明準備處理哪一段。」

| 要做的事 | 對 Agent 說 |
| --- | --- |
| 暫時停下來 | 「做到下一個段落就停，保存進度。」 |
| 準備換 Agent | 「準備交接，給我下一位 Agent 的接手摘要。」 |
| 請新 Agent 接手 | 「請依這份交接摘要接手 hahaha，繼續任務。」 |

新 Agent 仍由你開啟對話；你提供專案位置與交接摘要，工具操作由它負責。任務需求、必要決策及登入／OAuth／2FA 由你參與，其餘設定與復原交給 Agent。

需要共用秘密值時，再交代 Agent 設定 Doppler。秘密值留在 Doppler 或受信任的本機設定流程，不貼到對話。交接紀錄與主線合併／正式發布是分開的事情，整合或發布依你的指示進行。

技術步驟供 Agent 查閱：[Agent 與維護者操作手冊](agent-operations.zh-TW.md)。
