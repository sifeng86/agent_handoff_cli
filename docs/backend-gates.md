2026-10-09 的 [Update API](https://docs.doppler.com/reference/secrets-update) 調查未建立 expected revision／owner fence 契約。使用者其後明確批准基本同步；該強交易契約不再是 shared upload 的必要前提，Git owner precheck 也不被宣稱為 Doppler fencing。

官方 [Delete API](https://docs.doppler.com/reference/secrets-delete) 與 [List API](https://docs.doppler.com/reference/secrets-list) 是早期 adapter 調查參考。目前基本 CLI 的 authenticated upload/readback/delete 已完成隔離驗收，見 [實測紀錄](doppler-basic-evidence.json)。

Local OS timeout evidence: tests/test_git_timeout.py uses a controlled PATH Git wrapper with real subprocess descendants holding captured pipes. The normal GitBackend Popen path uses a fixture-only 0.5-second deadline; process-group cancellation is bounded and descendants are confirmed terminal. One case times out before executing the actual push and retains unknown/pending intent; another executes real conditional Git push, then stalls the reply process. The backend returns publication_unknown, runtime proves the exact accepted commit and resolves ownership without a second push. This is real process/deadline/cancellation evidence, not TCP packet loss, SSH authentication, delayed remote-server execution or GitHub timeout proof. Those transport scopes remain unverified.

Loopback TCP Git wire evidence: tests/test_git_tcp_timeout.py forwards real upload-pack/receive-pack frames over an ephemeral 127.0.0.1 socket through a fixture-only SSH shim. Two actual OS-deadline cases passed with loopback socket permission: withheld post-accept result frames resolve exact published commit; a gated real pre-receive hook stays active after client timeout while HEAD remains unchanged, pending operations block acquisition and resolve stays unknown, then delayed server acceptance resolves without replay. Exactly one additional receive-pack request is asserted per case. The shim provides neither SSH encryption nor authentication, and this is not GitHub packet-loss/branch-policy evidence. Standard suite execution requires allowed loopback sockets; restricted sandboxes must run this fixture through their approved network permission path.

A17 affirmative terminal evidence: the Git backend retains a bounded private stdout receipt after OS timeout and accepts only a complete single-ref rejection bound to the exact submitted OID/ref. A real local receive-pack pre-receive rejection precedes a stalled client reply; the old acquisition resolves rejected without a capability, then a new operation publishes one owner commit. Wrong identity or incomplete/ambiguous receipts retain unknown. This is a local Git backend contract case, not live hosting timeout or universal server-quiescence evidence. See [retained test evidence](git-terminal-rejection-evidence.json).
